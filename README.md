# openwsv — World-Model Grounding Benchmark

Static frontend (Vue 3 + Vite 6 + Tailwind CSS 4) for the **openwsv** benchmark:
**world-model grounding / world-state understanding**, not a full world-model evaluation.

> Given two frames and a slot table, the benchmark scores whether a vision-language model
> can ground a scene change into a structured **world-state update** — object changes,
> spatial relations, contact/support judgements and the resulting event stream.
> Any VLM can submit; entries are ranked by a 7-dimension equal-weight composite score.

**Scope:** single-step, two-frame grounding. Multi-step rollout, action-conditioned dynamics and
planning are **out of scope for v1** (planned as separate tracks). The page states this explicitly
so the leaderboard is never read as a full world-model ranking.

## Data source (single)

All numbers on the page come from static JSON generated by **`starlife_eval`** — there is no API
call at runtime and no mock/demo evaluation backend:

```
src/data/leaderboard.generated.json   # leaderboard contract, schemaVersion 4
src/data/confidence_intervals.json    # 95% pair-level bootstrap intervals
```

Regenerate the leaderboard with:

```bash
python -m starlife_eval leaderboard --run <run-dir> \
  --out third_party/openwsv/src/data/leaderboard.generated.json
```

Rules:

- `leaderboard.generated.json` is a **generated contract file** — never hand-edit it.
- Any metric that was not measured is `null`; the UI renders `N/A` (grey bar placeholder),
  never `0` and never a made-up value.
- If the file is missing or `models` is empty, the page shows an explicit empty state.
- `_note: "SAMPLE for dev only"` means a development sample is still in place and must be
  replaced by a real run before publishing.

## What the page shows

- **Score bars** above the table: 8 segmented buttons (Overall score + 7 dimensions), bar length
  sorted by the selected metric, 300 ms width transition, 95% CI whiskers drawn after each bar,
  family-colored bars (same family → same color), a non-interactive 9-item family legend, and a
  fixed note explaining the current metric.
- **Leaderboard table**: `[L]` local supervised head vs `[Z]` zero-shot cloud VLM track tags,
  per-dimension breakdown, Best badge per column, dimension tooltips, version switch.
- **Reading notes**: collapsible "How to read" covering scope, track difference, CI interpretation
  and the composite formula.
- Task examples, methodology and protocol sections; dark/light theme; English-only UI.

## Tracks and honesty rules

| Track tag | Meaning |
|---|---|
| `[L]` | supervised local head, in-domain training |
| `[Z]` | zero-shot general VLM via chat API |

- Track scores are **not mixed**: ranking across tracks is not a capability claim.
- Always read the 95% bootstrap intervals; overlapping intervals mean "indistinguishable", not
  "the same score".
- No single "best model" claim is published when intervals overlap.

## Composite score

- Equal-weight mean of 7 dimensions, each on a 0–100 scale.
- Dimensions: change identification top-1, change balance (macro-F1), relation type, spatial
  position, contact/support, event F1, state consistency.
- Missing dimensions are dropped from the denominator (never counted as 0).
- Per-dimension sources are listed in `meta.composite.dims[].source` in the generated JSON.

## Build and serve

```bash
pnpm install
pnpm build      # outputs dist/
```

`dist/` is a fully static site: serve it from any static host (a plain `python -m http.server`,
Nginx, or object storage). The build is reproducible from `src/data/*.json` alone.

## Provenance and related work

- This repository is the `openwsv` benchmark site. Its layout started from an early openwsv UI
  sketch; since v1.4 it ships **only real evaluation data** — the mock leaderboard and the demo
  evaluation backend were removed.
- Evaluation code, verifiers, report generation and confidence intervals live in the separate
  **`starlife_eval`** repository; the frontend consumes only its generated JSON.
- Positioning, scope boundaries and naming rules are recorded in `starlife_eval/docs/positioning.md`.
